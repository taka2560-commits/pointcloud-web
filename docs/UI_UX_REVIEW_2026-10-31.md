# UI / UX 精査レポート（デザインスタイル改修の準備）

> **改修の実施状況（2026-10-31 追記）**: 本レポートの所見に基づき、同日に新UI（modern）を実装しました。
> 対応した項目は §7 に一覧があります。本文の「根拠」で参照している改修前のスクリーンショットは `docs/ui_review/before/` に、
> 新UIのスクリーンショットは `docs/ui_review/` 直下に、従来UIモードで起動した画面は `docs/ui_review/classic/` にあります。
> 従来UIへの戻し方: 設定 → システム → UIスタイル、または起動引数 `--classic-ui`（AI_HANDOVER.md §2-⑦）。

- 実施日: 2026年10月31日
- 対象: デスクトップ版 GUI（`gui/main_window.py`, `gui/gl_viewer.py`, `gui/progress_dialog.py`, `gui/styles.py`）。Web 版はパレット比較のみ
- 方法: 実画面スクリーンショット（`tools/capture_ui_screens.py`、1600×900 / 1100×700、表示倍率 175%）、コードの静的監査、WCAG コントラスト計算（`tools/check_contrast.py`）
- 証跡: `docs/ui_review/*.png`（01 起動直後 〜 10 狭幅）
- 対象ユーザー: 測量士・土木/建築技術者。初心者からプロまで。現場 PC（ノート、HD〜FHD、拡大率 125〜175%）での利用が多いと想定

## 0. 総評（2秒の第一印象）

最初に目に入るのは左の濃密なサイドバー（約170個の操作部品が全展開）と、上部に並ぶ14個の絵文字付きボタンです。「何ができるツールか」は伝わりますが、「まず何をすればよいか」は伝わりません。3D ビューはグリッドとギズモだけで、ファイルを開く導線がありません。

一方で、機能の土台は良好です。非破壊のノイズレイヤー、Undo の常時案内、選択時だけ現れる下部アクションバー、現場レシピ、測量座標系対応など、「残すべき設計」が明確にあります。改修の主眼は **機能追加ではなく、情報の整理（減らす・まとめる・順番を揃える）と視覚言語の統一** です。

| 観点 | 評価 | 一言 |
| :--- | :---: | :--- |
| 機能性・安全性 | ◎ | 非破壊編集、Undo、中止可能な重処理、ロック保護 |
| 情報設計（何がどこにあるか） | △ | 同じ操作が3〜5か所に重複、作業順と配置順が不一致、約170部品が全展開 |
| 視覚的階層（何が重要か） | △ | 主アクセントが7色に分裂、主ボタンが3〜4種、機能別の虹色ボタン |

| 可読性・アクセシビリティ | △ | 実効 10〜11px の和文が多数、無効状態や注記のコントラスト不足、色のみの区別 |
| 応答性（画面サイズ） | △ | 1100px 幅で上部ツールバーと下部バーが切れる |

## 1. 良いところ（改修で必ず残す）

1. **非破壊ワークフロー**: 除去点は「ノイズレイヤー」に退避され、いつでも復元できる。差分 Undo/Redo と 🔒 ロック保護があり、トーストで「Ctrl+Z で取消可」を毎回案内している。
2. **重い処理の体験**: 進捗ダイアログ（中止・Esc 対応）、バックグラウンド実行、処理中に点群が変わったら結果を破棄する安全設計。
3. **文脈依存の操作**: 選択したときだけ有効になる下部アクションバー（件数バッジ付き）と、選択状態に応じた右クリックメニュー。
4. **初心者への配慮**: 現場シチュエーション別レシピ、各パラメータの「上げると／下げると」ツールチップ、ボタン名へのショートカット併記。
5. **測量実務向け機能**: 測量座標系の取り込み、フォルダ一括読込、`_cleaned` 自動命名、断面 HUD の数値表示、2点壁アライン、ギズモクリックでの視点切替。
6. **ダークテーマの基本方針**: 点群ビューアを主役にする暗色基調、本文テキストのコントラスト（10:1 前後）は十分。

### 2.3 可読性・アクセシビリティ（WCAG 2.1 コントラスト比、`tools/check_contrast.py`）

| 用途 | 文字 / 背景 | 比 | 判定 |
| :--- | :--- | ---: | :---: |
| 本文ラベル | #cccccc / #1e1e24 | 10.33 | AAA |
| グループタイトル | #38bdf8 / #172033 | 7.59 | AAA |
| 通常ボタン | #ffffff / #2e6296 | 6.36 | AA |
| **無効ボタン** | #777788 / #333340 | **2.83** | **NG** |
| **outline ボタン（無効）** | #555566 / #181820 | **2.42** | **NG** |
| **segment ボタン（選択・11px 太字）** | #ffffff / #0284c7 | **4.10** | **NG**（小文字は 4.5 必要） |
| **注記テキスト（10〜11px）** | #64748b / #172033 | **3.42** | **NG** |
| プライマリ実行ボタン（14px 太字） | #ffffff / #28a745 | 3.13 | AA（大文字扱い。13px 以下なら NG） |

- 無効状態は「読めなくてよい」ものではなく、「何があるか分かるが押せない」状態として 3.0 以上を目標にする。
- 色だけで意味を伝えている箇所: ノイズ=赤、通常=水色、平面=緑、地面=茶。凡例が無く、高さ配色（Turbo/Jet）の赤と区別できない。
- 極小の固定サイズ: 色見本 18×18、ロック 26×20、開閉 22×20、「正対」最大 40px。クリック目標は最小 24×24（推奨 28〜32）に。
- キーボード: `setTabOrder` やアクセシブル名の設定なし。フォーカスリングはフォーカス枠色（#4da6ff）のみ。

### 2.4 画面サイズへの追従（`10_narrow_1100x700.png`）

- 1100px 幅では上部ツールバーの各ボタンが文字の途中で切れ（「ィット(F」「影: 透」）、右端の点数バッジも欠ける。
- 下部アクションバーがステータス文と重なり、ボタンが切れる（「ノイズ削除(D」「択内のみ精」）。トーストも右端のボタンに重なる。
- ノート PC（1366×768、125%）では実効幅が約1090px になるため、**現場でこの状態になる可能性が高い**。
- 推奨: ツールバーはアイコン化＋溢れ分を「…」メニューへ。下部バーは折り返しまたは優先度の低いボタンをメニューへ。サイドバーの最小幅を 320px に。

## 4. 改修の優先順位（提案）

1. **デザイントークンの導入と QSS の一本化**（V1〜V3, V7〜V10）: 見た目の一貫性はここで 8 割決まる。既存の `role` プロパティ方式を拡張し、インライン QSS を段階的に撤去する。詳細は `docs/DESIGN_STYLE_PLAN.md`。
2. **アイコン化と文字サイズの底上げ**（V5, V6, 2.3）: 絵文字 → SVG アイコン、最小 12px、無効状態のコントラスト 3.0 以上。
3. **情報設計の整理**（U1, U2, U6, U7）: 操作モードは縦ツールバーへ、サイドバーは「作業ステップ順」、ステータスバー新設。ホットファイル（main_window.py）への大きな変更になるため元AIと調整して1フェーズにまとめる。
4. **安全性の底上げ**（U4, U5, U9）: 変更フラグ、読込トリガーの明示化、破壊操作の件数プレビュー。
5. **応答性**（2.4）: ツールバーの溢れメニュー、下部バーの折り返し。

## 5. 本レビュー中に行った修正

- `gui/main_window.py` CollapsibleGroupBox: セレクタ無しの `background: transparent;` が子孫へ伝播し、グローバル QSS（`QPushButton#execute_button` の緑背景など）を打ち消していた問題を修正（objectName で自分自身に限定）。修正前: `docs/ui_review/11_before_fix_tab_auto.png`（実行ボタンが白い文字だけに見える）／ 修正後: `docs/ui_review/03_tab_auto.png`（緑の主ボタン）。本文 V4。
- `tools/capture_ui_screens.py`: 実画面を撮影する UI レビュー用ツール（デスクトップ全体を撮ってウィンドウ領域を切り出す。`win.grab()` は GL 上のオーバーレイを含まず、`grabFramebuffer()` はフローティングバーを隠し、`grabWindow(winId)` は GL 合成ウィンドウで古いフレームを返すため）。
- `tools/check_contrast.py`: 現行テーマのコントラスト比算出。

## 6. 改修前に決めていただきたいこと

1. **テーマ**: ダークのみ継続か、ライト／ハイコントラストも用意するか（現場の屋外では明るいテーマの需要があり得る）。
2. **アイコン**: 絵文字を全廃して SVG アイコンに置き換えてよいか（配布サイズ +数百KB、日本語ラベルは併記）。
3. **情報設計の規模**: 「見た目だけ統一（低リスク）」で止めるか、「操作モードの集約・ステップ型サイドバー（中リスク、main_window.py 大改修）」まで行うか。
4. **用語の統一案**: 「削除／消去／除去」→「ノイズへ移動」、「有効点群／通常点群」→「通常レイヤー」。レシピ名・ボタン名の「！」や誇張表現の整理。
5. **最小対応解像度**: 1366×768 @125%（実効 1093×614）を保証対象にするか。
